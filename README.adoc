= Umath: UnicodeMath parser for Ruby

image:https://img.shields.io/gem/v/umath.svg["Gem Version", link="https://rubygems.org/gems/umath"]
image:https://github.com/plurimath/umath/actions/workflows/test.yml/badge.svg["Build Status", link="https://github.com/plurimath/umath/actions/workflows/test.yml"]

== Purpose

Umath parses https://www.unicode.org/notes/tn28/[UnicodeMath], the
linear format for mathematics described in Unicode Technical Note 28, into a
typed model of the formula. It reads the UnicodeMath that
https://github.com/plurimath/plurimath[Plurimath] reads, with the same
grammar, and is built for Plurimath to use for UnicodeMath input
(https://github.com/plurimath/plurimath/issues/530[plurimath/plurimath#530]).

The model records the structure of the formula: which symbols, fractions,
scripts, roots, matrices and brackets it contains, and how they nest. Your
code decides what to do with it, such as rendering, converting or analysing
it. Umath does not write MathML or any other output format; Plurimath
does that.

== Installation

Add it to your `Gemfile`:

[source,ruby]
----
gem "umath", "~> 0.1.0"
----

Umath needs Ruby 3.2 or later. Its runtime dependencies are
https://github.com/parsanol/parsanol-ruby[Parsanol] and
https://github.com/lutaml/lutaml-model[LutaML Model]. It does not load
Plurimath.

== Usage

[source,ruby]
----
require "umath"

doc = Umath.parse("a/b")
frac = doc.expression.frac
frac.numerator.atom.alphanumeric.spelling   # => "a"
doc.to_hash
# => {"expression" => {"frac" => {"denominator" => {...}, "numerator" => {...}}}, "decimal" => "."}
----

`Umath.parse` returns a `Umath::Model::Document`. Its
`expression` holds the formula and `decimal` the decimal marker it was parsed
with. Input with no formula, such as an empty string, gives a document whose
`expression` is nil.

The model classes are plain LutaML Model classes, generated from the grammar:
each named part of the grammar is a class with one attribute per part it can
contain. Parts that can hold a whole expression, such as a numerator or a
subscript, share the class `Umath::Model::Expression`. Symbols are
`Umath::Model::MathSymbol` objects with the text the grammar matched
(`spelling`), its Unicode text (`value`) and its kind:

[source,ruby]
----
symbol = Umath.parse("α").expression.factor.ordinary_symbols
symbol.spelling # => "&#x3b1;"
symbol.value    # => "α"
symbol.kind     # => "symbol"
----

The spelling is the text after the input has been rewritten as Plurimath
does (non-ASCII characters become HTML entities), so `value` is usually the
field you want.

Numbers keep their digits and decimal marker as written. A dot is the
decimal marker unless you say otherwise; a comma and the Arabic decimal
separator are also supported:

[source,ruby]
----
Umath.parse("1,5", decimal: ",")
Umath.parse("1٫5", decimal: "٫")
----

The rules for each model class are in link:docs/model-contract.adoc[the
model contract], and the accepted syntax and the preprocessing of the input
in link:docs/parser-contract.adoc[the parser contract].

== Errors

Input that is not valid UnicodeMath raises `Umath::ParseError`, which
tells you where the parser gave up, as a position in the text you passed:

[source,ruby]
----
begin
  Umath.parse("α)")
rescue Umath::ParseError => e
  e.char_offset # => 1, position in characters
  e.byte_offset # => 2, position in UTF-8 bytes
end
----

Every error Umath raises on purpose is a `Umath::Error`, except
`ArgumentError` for an invalid argument, such as input that is not a valid
UTF-8 string, an unknown engine or an unsupported decimal marker.
`Umath::NestingTooDeep`, a kind of `ParseError` with no offsets, means
the engine could not handle how deeply the input nests, not that the input
is invalid.

== Engines

Umath runs its grammar on Parsanol's pure Ruby engine or on its native
engine. The default is `engine: :ruby`. You can opt into the native engine
with `engine: :native`, or with `engine: :auto`, which uses the native
engine where its extension is available and the Ruby engine elsewhere.
Asking for `engine: :native` where it cannot run raises
`Umath::EngineUnavailable` instead of quietly using Ruby.
`Umath.last_engine` tells you which engine handled the last call on
the current thread.

Ruby is the default because it is the engine that matches legacy Plurimath.
Up to Parsanol 1.3.133 the native engine returned a different tree on 18
inputs from the testsuite's `fixtures/unicode-expectations.yaml`; from 1.3.134
it returns the legacy tree for those inputs too. The native engine is faster, and the Ruby engine is slower,
especially on input it refuses. Choose `engine: :native` when speed matters.

== Testing against the Plurimath testsuite

The UnicodeMath cases of
https://github.com/plurimath/plurimath-testsuite[plurimath-testsuite] are
kept there as numbered, immutable generations.
`spec/fixtures/testsuite-pin.yml` names the exact commit, generation and
digest this gem is tested against, and CI replays every raw-tree row of that
generation on both engines. CI also compares the parse tree with the one the
pinned Plurimath commit produces for every UnicodeMath case of the testsuite.
See link:docs/testsuite-pin.adoc[the testsuite pin].

== Relation to Plurimath

Umath is one of the language gems split out of Plurimath, with
https://github.com/plurimath/amath[amath] for AsciiMath and
https://github.com/plurimath/latexmath[latexmath] for LaTeX. The plan and its
progress are tracked in
https://github.com/plurimath/plurimath/issues/541[plurimath/plurimath#541].
Plurimath is to turn the model into its own formula objects and write the
output formats.
