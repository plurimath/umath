= UnicodeMath model contract
:toc:

== Scope

`Unicodemath.parse(input, decimal: ".", engine: :auto)` returns a
`Unicodemath::Model::Document`, the typed UnicodeMath language model. This
document describes that model: how it is built from the grammar, what its
fields hold, and how it is checked. The rules shared by all stage gems
(API shape, errors, engines, artifacts, corpus pins) are in the stage
profile, amath's
https://github.com/plurimath/amath/blob/main/docs/stage-contract.adoc[`docs/stage-contract.adoc`];
this document only adds what is specific to UnicodeMath. The grammar,
preprocessing and the raw tree are described in
link:parser-contract.adoc[the parser contract].

The model is the UnicodeMath model, not a shared one. Mapping it to
Plurimath's `Formula` classes is Plurimath's job.

== Construction

The grammar binds its one root capture twice. The `raw` binding keeps the
legacy tree with its slices and offsets, for parity replay and error
positions. The `any` binding (path `model`) gives the same tree as plain
hashes, arrays and strings. `Model::Document.new` receives that tree, and
lutaml-model builds every nested node from the declared attribute types. No
gem code walks the parse tree to build the model.

After construction, one separate pass resolves symbols (see below).

=== Classes and fields

The model follows the grammar's captures. A capture is a name in the
grammar (`frac`, `numerator`, `sup_exp`, `nary_class` and so on), and the
model uses the same names:

* A capture whose value is a node becomes a class named after it, for
  example `frac` becomes `Model::Frac` and `decimal_number` becomes
  `Model::DecimalNumber`. Two names are changed so they do not shadow Ruby
  classes: `array` becomes `ArrayNode` and `symbol` becomes `SymbolNode`.
* Captures that hold a whole expression share one class, `Model::Expression`.
  These are the captures with 25 or more possible inner captures, such as
  `expr`, `exp`, `factor`, `numerator`, `denominator`, `base`, `sub`, `sup`
  and `first_value`.
* Each class declares one attribute for every capture that can appear
  directly inside it. An attribute has the same name and the same type in
  every class that declares it.
* A capture that can repeat (the grammar can give it an array) is a
  collection attribute. A single node in that position becomes a
  one-element collection.
* A capture whose value is text becomes a String attribute, or a
  `Model::MathSymbol` attribute for the captures that the legacy transform
  resolves through the symbol catalog: `alphanumeric`, `operator`,
  `ordinary_symbols`, `relational_symbols`, `nary_class`, `unicode_symbols`,
  `accent_symbols`, the paren prefixes and similar.
* Some node captures can also hold plain text, when the grammar matched no
  inner capture. Those classes declare a `literal` attribute, and the text
  goes there. For `open_paren`, `close_paren`, `symbol` and
  `prime_accent_symbols` the literal is a `MathSymbol`; elsewhere it is a
  String. For example, the base of `x^2` is a `SymbolNode` whose literal is
  the symbol `x`.

These rules give 77 node classes plus `MathSymbol` and `Document`. The
classes are in `lib/unicodemath/model/nodes.rb`, and the exported
declarations, with every field and its type, are in
`model/unicodemath.lml.json`.

Text fields keep the text the grammar matched. The grammar runs on the
preprocessed, entity-encoded input, so non-ASCII text appears as character
references: a `text` capture for `"αβ"` holds `&#x3b1;&#x3b2;`. This is the
same text the legacy transform received. `MathSymbol#value` gives the
Unicode text of a symbol.

=== Document

`expression`:: The formula's tree, an `Expression`.
`label`:: The equation label: the text after the last `#`, or nil when the
input has none. This follows the legacy facade. A `#` inside `✎(...)` does
not start a label.
`decimal`:: The decimal marker the input was parsed with.

=== Numbers

Numbers are kept as written. `number` is the digit string, and
`DecimalNumber` has `whole`, `decimal` (the marker as matched, for example
`.` or `&#x66b;`) and `fractional`. Nothing is converted to a float.

== Symbol resolution

`Unicodemath::Symbols.resolve` visits every `MathSymbol` and looks its
spelling up in `data/unicodemath-symbols.json`. That file is the legacy
symbol catalog exported from the pinned Plurimath commit. Like the legacy
transform, the lookup uses the spelling with surrounding whitespace
removed.

`spelling`:: The token as the grammar matched it, for example `&#x3b1;` for
`α` or `alpha` for `\alpha`.
`value`:: The Unicode text the catalog entry writes as UnicodeMath, for
example `α`.
`kind`:: `symbol` or `paren` for catalog entries. When the catalog has no
entry the kind is `unlisted`, and the value is the spelling with its
character references decoded. The legacy transform keeps such a spelling
as a plain symbol.

== Errors and positions

Errors follow the stage profile. A `ParseError` reports `input` (the
caller's text as UTF-8), `char_offset` and `byte_offset`, both measured in
the caller's text. The grammar reports positions in the preprocessed text.
`Unicodemath::SourceMap` repeats each preprocessing step on the caller's
text and records where every character came from, so a grammar position can
be mapped back. Characters produced by one replacement, such as the
`&#x3b1;` that stands for `α`, all map to the position of the original
character. The end of the grammar input maps to the end of the formula part.

Input with no formula is refused with a `ParseError` at offset 0. That is
an empty string, or a string made only of `#` label separators. The legacy
facade fails on such input with `NoMethodError`, so it has no defined
result to keep. An empty formula before a label, such as `#b`, reaches the
grammar and is refused there.

`NestingTooDeep` is raised when the engine cannot handle the input's depth.
That includes the Ruby stack running out while the model is built. In
measurements on the Ruby engine, the grammar reached its limit first in
every case: 400 chained terms or 100 nested parentheses failed in the
grammar, and every input the grammar accepted (up to 200 chained terms, 50
nested parentheses and 100 nested fractions) was built without error.

== Checks

* `spec/model/model_shape_spec.rb` computes, from
  `data/unicodemath-grammar.json` and Parslet's flattening rules, which
  values each capture can hold. It then requires that every capture is
  declared, with a type and collection flag that can hold all of those
  values, and that every class that can receive text declares `literal`.
* `Model::CaptureTree` turns a model back into a capture tree and compares
  it with the tree the bindings produced. lutaml-model ignores keys that a
  class does not declare, so this is how a missing declaration is caught.
  It also fails when an attribute holds a value of the wrong type.
* `scripts/replay_corpus.rb --staging corpora/model` replays the
  representative rows in `corpora/model/`. For each row it checks the
  capture tree and compares the document with the stored expectation. The
  expectations are the gem's own output, so they guard against regressions;
  they are not legacy parity.
* In the replay workflow, every fixture and authored oracle row also runs
  through the model (`scripts/replay_corpus.rb --inventory ... --rows ...`).
  A row the legacy grammar accepted must build a model with a matching
  capture tree, and a row it refused must raise `ParseError`. The report
  counts, for each capture, the kinds of value it held across the corpus.
  The raw-tree replay itself is unchanged.
* `scripts/verify_lml.rb` exports every model class with
  `Lutaml::Model::Lml.export`, requires the committed
  `model/unicodemath.lml.json` and `model/unicodemath.lml.checksums.txt` to
  be byte-identical to a fresh export, and runs `Lutaml::Model::Lml.verify`
  on each document. `Lml.verify` re-exports the loaded Ruby class, so it
  does not prove that another implementation can rebuild the model. The
  model uses no union types, which LML export rejects. Text in node
  positions is handled by the `literal` declaration together with
  `Node.cast`, not by unions.
